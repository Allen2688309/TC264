# 复位排查修改

本次未改电机、舵机、编码器参数及3ms控制周期。

## 修改

- CPU0主栈从2KB改为8KB，中断栈从1KB改为4KB。旧map的整体栈估算为0x11e0（4576字节），有递归标记；core0_main普通调用链估算1040字节。因此栈余量是风险项，不能据此确认发生过溢出。旧map显示CPU0 RAM有余量，新配置需重新链接确认。
- 摄像头暖机不再无限等帧。暖机和运行统一100ms超时，超时返回无效帧，不继续处理旧图，交给现有丢帧保护处理。
- 删除右侧只写不读的方向数组，左侧方向改为uint8，节省1080字节RAM。
- 删除Menu_Init中的重复屏幕初始化，屏幕只在CPU0主函数初始化。
- 初始化前记录SCU_RSTSTAT，保留原有三声启动提示。STATUS页用RSTH/RSTL显示高低16位（十进制），CTO显示等帧超时次数。计数达到65535后不再增加。
- 精简CPU0主函数和部分过时注释。屏幕SPI实际是阻塞发送，原注释称DMA不占CPU时间不准确，已修正。

## 查看诊断

复位状态原值 = RSTH × 65536 + RSTL。位定义来自工程TC26B寄存器头文件：

- 位0/1：ESR0/ESR1外部复位请求。
- 位3：SMU请求，需进一步查看报警源，不能单凭此位断定看门狗。
- 位4：软件复位请求。
- 位16：PORST复位。
- 位23/24：EVR13/EVR33复位。
- 位25：供电看门狗。
- 位28：待机稳压器看门狗。

本次不清除硬件复位标志，部分标志可能保留历史状态。出现PORST也不能仅凭代码断定欠压，需结合供电和复位引脚测量。CTO增长说明等待完整图像超时，不等同于芯片复位。启动三声再次出现是主程序重新启动的线索；没有听到提示不能排除复位。
